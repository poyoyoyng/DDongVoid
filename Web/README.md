# 포요용의 미니게임천국

**증윷**이 추가되었습니다. 공용 대기방에서 증윷 방을 만들고 2~4명이 모두 준비 완료를 누른 뒤 **증윷 게임판 열기**를 누릅니다. 기존 웹 계정·관전·자리 승계·랭킹을 사용하며, 온라인 판은 기존 Durable Object에 저장합니다. AI·같은 기기 연습은 게임판의 연습 버튼으로 별도로 시작합니다.

일반 윷놀이처럼 말 4개를 모두 완주하면 승리합니다. 각자의 5·10·15턴에 증강 3개 중 하나씩 선택하고, 총 17종의 증강이 있습니다. 알까기는 내 알을 뒤로 당겼다 놓으면 반대 방향으로 날아가고, 당긴 길이가 파워를 정합니다. 명중하면 상대 묶음이 탈락하며, 빗나가면 내 묶음이 탈락해 대기로 돌아갑니다. 플레이어는 좌우 2명씩, 윷 던지기·행동 안내는 중앙에 표시합니다.

도파민장아찌는 선택한 자신의 턴을 포함한 7턴 동안 전진 +1칸, 이후 10턴 동안 −1칸이며 끝나면 정상 이동합니다. 상대 묶음 잡기 또는 내 말 완주 한 번당 디버프가 1턴 줄어듭니다. 버프 중 성공도 이후 디버프에서 미리 차감하고, 추가 던지기만으로 턴이 줄지는 않습니다. 알까기 명중도 잡기로 인정하지만 빗나감·방어로 막힌 공격은 차감하지 않습니다. 업힌 말을 여러 개 잡거나 함께 완주해도 한 행동당 1턴이며 남은 기간은 0보다 작아지지 않습니다. 빽도는 그대로이고 전진 거리가 0칸이면 정지합니다.

성어말?은 전진 이동을 확정할 때 +1칸 15%, −1칸 15%, 정상 이동 70%로 도착지가 달라집니다. 미리보기는 예정 목적지이며 실제 도착 칸에서 잡기·업기·완주를 판정합니다. 업힌 묶음은 한 번만 판정하고 함께 이동하며, 빽도·알까기에는 적용하지 않습니다. 전진 거리는 최소 0칸입니다. 판정은 온라인 서버가 하며 클라이언트가 이동 보정값을 정할 수 없습니다.

뒹학 사람좀 모아봐는 정확히 내 말 2개가 완주하고, 창고의 말 하나와 판 위에서 달리는 내 말이 있을 때 판당 한 번 사용합니다. 창고 말을 달리는 말의 위치·지나온 경로에 그대로 업고, 남은 윷 결과·추가 던지기·알까기 기회를 포기해 즉시 다음 사람에게 턴을 넘깁니다. 증강 선택 중·게임 종료 후에는 사용할 수 없습니다. 업기는 일반 전진 이동이 아니므로 이동 보정·잡기·완주 보너스가 발동하지 않습니다. 사용 버튼과 남은 1회는 중앙 행동 영역과 플레이어 카드에 표시합니다.

증윷 화면과 공용 규칙은 `public/jeung-yut/`, 기존 방 연결은 `src/jeungyut.js`에 있습니다. 웹 기능 수정은 **`codex/web-production` 브랜치와 `Web` 폴더**에서 진행합니다.

브라우저에서 똥 피하기, 키보드 리듬, 니편내편, 맞짱, 차오차오, 원카드, 야추, 오목, 섯다, 사보타지, 다빈치 코드, 부루마불을 플레이할 수 있습니다. Windows 앱은 저장소 루트의 `실행.cmd`로 계속 실행합니다. 웹은 자체 계정과 랭킹을 사용하고 Windows 앱은 기존 JSON 저장 폴더를 사용합니다.

웹의 **대기방**에서 맞짱, 차오차오, 원카드, 야추, 오목, 섯다, 사보타지, 다빈치 코드, 부루마불 방을 한 번에 확인할 수 있습니다. **방 만들기**에서 게임과 제목을 지정하면 방이 목록에 올라갑니다.
대기방에서는 로그인한 이용자와 대화할 수 있고, 게임방에서는 참가자와 관전자가 함께 대화할 수 있습니다. 각 채팅창은 최근 메시지 50개를 보여 줍니다.

**키보드 리듬**은 Windows 앱과 같은 규칙입니다. 왼손(S·D)·오른손(K·L) 두 라인에 내려오는 블록을 판정선에서 누르고, PERFECT·GREAT·GOOD 판정과 콤보로 점수를 얻습니다. MISS마다 라이프가 25% 줄어 0%가 되면(MISS 4번) 끝나며, 모바일에서는 화면 아래 S D K L 버튼으로 칩니다. 웹 기록은 웹 랭킹에만 올라갑니다.

**니편내편**은 웹 전용 싱글 게임입니다. 캐릭터 6종(문어·까까머리·양·식빵·분홍냥·도깨비)이 왼쪽과 오른쪽에 세 마리씩 서 있고, 가운데 줄 맨 앞 캐릭터를 같은 캐릭터가 있는 쪽으로 ← → (또는 A D, 화면 왼쪽·오른쪽 터치)로 보냅니다. 줄의 캐릭터는 무작위로 나옵니다. 체력은 100에서 시작해 초당 6씩 줄고, 플레이 1분마다 6씩 빨라져 5분 이후 초당 36이 됩니다. 맞히면 체력 +4, 틀리면 체력 −12와 콤보 초기화이며 틀린 캐릭터는 맨 앞에 남습니다. 한 마리당 점수는 100 + 콤보 × 10점(콤보 100부터 1,100점)입니다. 플레이 시간 30초마다 시간이 멈추고 「섞어!!」와 함께 여섯 마리의 자리가 바뀌며(적어도 한 마리는 반대편으로), 「다시 시작!」 뒤에 이어집니다. 섞는 동안에는 체력이 줄지 않습니다. 캐릭터 그림은 `public/sides-art.js`의 SVG입니다.

**오목**은 15×15 판에서 렌주룰(RIF)로 둡니다. 흑이 먼저 두고 정확히 다섯 개를 이어야 이기며, 흑의 3-3·4-4·장목은 금수라 그 자리에 둘 수 없습니다(판에 × 표시). 백은 제한이 없고 장목도 승리입니다. 흑과 백은 같은 방에서 한 판씩 번갈아 맡고, 첫 판은 P1이 흑입니다.

**섯다**는 화투 20장(1~10월 두 장씩)으로 2~4명이 하는 2장 섯다입니다. 판마다 모두 기본 판돈 1만원을 내고, 한 장을 받아 베팅하고 한 장을 더 받아 다시 베팅한 뒤 남은 사람끼리 족보를 비교합니다. 베팅은 다이·체크·콜·삥(1만원)·따당(앞 베팅의 2배)·하프(콜 후 판돈의 절반)이고, 30초 안에 고르지 않으면 체크할 수 있을 땐 체크, 아니면 다이입니다. 광땡·땡·알리~세륙·끗 순이며 암행어사(13·18광땡 잡기), 땡잡이(1~9땡 잡기), 구사·멍텅구리 구사(재경기)가 있습니다. 족보가 같으면 판돈을 나눕니다. 한 판에 걸 수 있는 돈은 그 판 참가자 중 가장 적은 잔액까지입니다. 판 도중 관전석으로 이동하면 다이로 처리하고, 그 자리는 판이 끝날 때까지 비워 둡니다. 화투 그림은 Wikimedia Commons의 [SVG Hwatu](https://commons.wikimedia.org/wiki/Category:SVG_Hwatu)(Spenĉjo · Marcus Richert · Louie Mantia, Jr., CC BY-SA 4.0)를 쓰며 출처는 `public/assets/hwatu/CREDITS.txt`와 게임설명에 적어 두었습니다.

**사보타지**는 3~10명이 하는 숨은 역할 게임입니다(AMIGO Saboteur 기본판 규칙). 라운드마다 역할을 비밀리에 받아 광부는 시작 카드에서 7칸 떨어진 목적지 3장(금 1·돌 2) 중 금까지 굴을 잇고, 방해꾼은 몰래 막습니다. 광산은 세로 5줄(목적지 3장이 놓인 줄과 그 사이)이고 시작 카드가 왼쪽 끝이라 그 왼쪽에는 카드를 놓을 수 없습니다. 방해꾼은 규칙대로 3·4명 1명, 5·6명 2명, 7~9명 3명, 10명 4명이 언제나 나오고 나머지는 모두 광부입니다(원작처럼 역할 카드를 한 장 남기지 않음), 손패는 3~5명 6장, 6~7명 5장, 8~10명 4장입니다. 카드는 길 40장(막다른 길 9장 포함)과 행동 27장(도구 부수기 9, 고치기 9, 지도 6, 낙석 3)입니다. 차례마다 길 카드를 놓거나 행동 카드를 쓰거나 한 장을 버리고 패스한 뒤 한 장을 뽑으며, 도구가 하나라도 부서지면 길 카드를 낼 수 없습니다. 광부 팀과 방해꾼 팀이 한 판으로 겨루는 팀전입니다(원작은 3라운드 동안 금 카드를 나눠 가짐). 누구든 길이 금 목적지에 닿으면 광부 전원이 이기고, 카드가 모두 떨어질 때까지 금을 못 찾으면 방해꾼 전원이 이기며, 랭킹에는 이긴 팀 전원이 승리로 기록됩니다(Elo). 차례 60초가 지나면 첫 손패를 버리고 패스하며, 카드 그림은 원작 분위기를 따라 SVG로 새로 그렸습니다(`public/saboteur-art.js`).

**다빈치 코드**는 2~4명이 하는 숫자 추리 게임입니다(나무위키 기본 규칙). 패는 검은·흰 0~11과 조커 2장, 모두 26장이고 2~3명은 4장, 4명은 3장씩 조커 없이 받습니다. 패는 왼쪽부터 작은 수 순서이고 숫자가 같으면 검은 패가 왼쪽이며, 상대에게는 색만 보이고 숫자는 보이지 않습니다. 차례마다 검은 패와 흰 패 중 색을 골라 한 장 가져와 순서대로 끼우고(조커는 원하는 자리, 조커 옆에 들어갈 숫자 패도 자리를 고름), 상대의 숨긴 패 하나를 골라 0~11 또는 조커를 말합니다. 맞히면 그 패가 공개되고 계속 추리하거나 멈출 수 있으며(멈추면 가져온 패는 숨긴 채로 남음), 틀리면 가져온 패를 공개하고 차례가 끝납니다. 더미가 비면 가져오지 않고 추리만 하며, 틀리면 자기 숨긴 패 하나를 골라 공개합니다(나무위키에 없는 부분은 공식 규칙을 따름). 패가 모두 공개되면 탈락하고 마지막까지 남은 사람이 이기며 Elo 랭킹에 반영합니다. 단계마다 60초가 지나면 많은 쪽 색을 가져오기, 첫 자리에 놓기, 맞힌 뒤면 멈추기·추리 전이면 틀린 것으로 처리, 가장 왼쪽 숨긴 패 공개 순으로 자동 진행합니다. 숨긴 패 아래에는 누군가 말했다가 틀린 숫자를 표시합니다.

**부루마불**은 2~4명이 하는 씨앗사 부루마불입니다. 땅값·건물값·통행료와 황금열쇠는 나무위키 「부루마불/주요 카드」를 따랐고, 판은 출발·무인도·사회복지기금 수령처·우주여행을 모서리로 하는 40칸(도시 23·관광지 3·탈것 3·황금열쇠 6·사회복지기금 접수처)입니다. 말은 자리 순서대로 꼬마 히어로(빨강)·삐약이(노랑)·꼬마 경찰(파랑)·아기 공룡(초록)이고, 산 땅은 같은 색 테두리와 깃발로 표시되며, 판 가운데에 방금 일어난 일(주사위·구입·통행료와 오간 돈)이 크게 뜹니다. 3~4명은 293만원, 2명은 586만원으로 시작하고 출발을 지나거나 멈추면 월급 20만원을 받습니다. P1부터 주사위 2개를 굴려 이동하고, 더블이면 한 번 더 굴리며 더블 3번이면 무인도로 갑니다(원작에 없는 널리 쓰는 규칙). 주인 없는 땅은 살 수 있고, 내 도시에 다시 서면 별장 2채·빌딩·호텔을 순서 없이 지을 수 있으며, 통행료는 땅 통행료와 지은 건물 통행료를 모두 더합니다. 무인도는 3턴(더블 또는 탈출권으로 탈출, 3번째 턴에는 굴린 만큼 나감), 접수처는 기금 15만원 내기, 수령처는 모인 기금 받기, 우주여행은 다음 차례에 원하는 칸으로 이동(컬럼비아호 주인에게 20만원)입니다. 황금열쇠 30장 중 우대권(통행료 1회 면제)과 무인도 탈출권은 갖고 있다가 씁니다. 돈이 모자라면 땅을 싼 것부터 은행에 반값으로 자동 매각하고, 그래도 모자라면 파산해 땅이 은행으로 돌아갑니다. 굴리기 전에는 내 땅을 직접 반값에 팔 수 있습니다. 혼자 남으면 이기고, 30라운드가 끝나면 현금+땅값+건물값의 총자산이 가장 많은 사람이 이깁니다(같으면 무승부). 결정마다 30초가 지나면 주사위는 대신 굴리고, 땅 사기·건물 짓기는 넘어가고, 우주여행은 출발로 갑니다.

**관전**으로 경기 중인 방에도 입장할 수 있습니다. 방에서 참가자와 관전자 이름을 확인할 수 있습니다. 참가자는 언제든 **관전석으로 이동**할 수 있고, 빈자리가 있으면 관전자는 **참가하기**로 그 자리에 앉을 수 있습니다. 경기 중 빈자리가 생기면 그 자리에 누군가 앉을 때까지 경기가 멈춥니다. 경기 도중 다른 사람이 자리를 이어받은 판은 랭킹에 반영되지 않습니다.

## 로컬 실행

저장소 루트에서 Node.js 22 이상과 npm으로 실행합니다.

```powershell
cd Web
npm ci
npm run dev
```

`http://localhost:8787`에 접속해 로그인 창에서 **회원가입**을 선택하고 닉네임과 4자 이상의 비밀번호를 입력합니다. 예전에 발급받은 접속 키는 로그인 화면의 비밀번호 칸에서 계속 사용할 수 있습니다. 로컬 D1과 대전방 상태는 `Web/.wrangler`에 저장됩니다.

`npm run check`로 게임 규칙을 검증합니다. 개발 서버가 실행 중이면 별도 터미널에서 `npm run check:worker`로 가입, 대전 WebSocket, 차오차오 20초 자동 PASS, 랭킹 저장을 검증할 수 있습니다. 이 통합 테스트는 실행 중인 로컬 DB에 테스트 계정과 경기를 추가합니다.

## Cloudflare 배포

`Web`에서 실행합니다. 첫 배포에만 Wrangler 계정 연결과 D1 생성이 필요합니다. `--location=apac`은 D1 데이터베이스의 아시아 태평양 배치 힌트입니다.

```powershell

# 아래 배경음악 절의 MP3 파일을 준비한 뒤, 최초 한 번 음원 서비스를 배포합니다.
npm run deploy:music
npm run deploy
```

이후 업데이트에는 `npm run deploy`를 사용합니다. 이 명령은 정적 자산을 준비하고 D1 마이그레이션을 적용한 뒤 Worker를 배포합니다.

배포 출력의 `workers.dev` 주소에서 접속할 수 있습니다. 커스텀 도메인을 쓸 경우 Worker의 **설정 → 도메인 및 경로**에서 Cloudflare에 등록된 도메인을 연결합니다.

GitHub 자동 배포에는 같은 Worker의 Workers Builds를 사용합니다. 운영 브랜치는 `codex/web-production`, 루트 디렉터리는 `Web`, 빌드 명령은 `npm run check`, 배포 명령은 `npm run deploy`로 설정합니다. 빌드 토큰에는 Workers와 D1 편집 권한을 부여합니다. 운영 데이터베이스는 운영 브랜치에서만 마이그레이션합니다.

## 배경음악

음원 저장 위치, 장애 원인, 배포 시 지켜야 할 규칙은 [MUSIC.md](MUSIC.md)에 정리되어 있습니다. 음악·자산·Cloudflare 배포를 수정하기 전에 먼저 확인합니다.

로그인한 이용자에게만 배경음악을 재생합니다. R2나 결제수단 등록 없이 별도 비공개 Worker `ddongvoid-music-assets`에 MP3를 보관합니다. 사이트 Worker는 로그인 확인 후 `MUSIC_ASSETS` 서비스 바인딩으로 음원을 읽습니다. 음원 Worker는 공개 주소와 미리보기 주소를 모두 비활성화하며, 사이트의 자동 배포와 독립적으로 유지됩니다. 홈페이지 상단 플레이어에서 현재 곡과 가수를 확인하고 시작, 일시정지, 다음 곡, 재생 목록 선택과 볼륨 조절을 할 수 있습니다. 현재 시간과 전체 길이를 표시하고, 진행 막대를 움직여 재생 위치를 바꿀 수 있습니다. 볼륨 표시는 0~100%이며 첫 방문 기본값은 50%입니다. 실제 출력에는 0.15를 곱합니다. 여섯 곡을 순서대로 재생한 뒤 처음부터 반복하고, 선택 곡·볼륨·일시정지 설정은 브라우저에 기억합니다. 키보드 리듬 화면에서는 BGM이 자동으로 멈추고, 화면을 나가면 이전 재생 상태로 돌아옵니다. 브라우저 정책상 첫 클릭이나 시작 버튼을 누른 뒤 음악이 나올 수 있습니다.

`Web` 폴더에서 아래 여섯 음원을 준비하고, 최초 설정 또는 곡을 추가·교체할 때만 음원 서비스를 배포합니다. MP3는 Git에서 제외됩니다.

```powershell
New-Item -ItemType Directory -Path public/api -Force
Copy-Item -LiteralPath "C:\경로\노래.mp3" -Destination public/api/music.mp3
# 여섯 곡을 모두 준비한 뒤 실행합니다.
npm run deploy:music
```

곡 목록은 `public/music-library.js`에서 관리합니다. 현재 배포하는 음원 파일은 다음과 같습니다.

| 곡 | 로컬 배포 파일 |
| --- | --- |
| Kelly Clarkson — Underneath The Tree | `public/api/music-files/underneath-the-tree.mp3` |
| Mariah Carey — All I Want For Christmas Is You | `public/api/music-files/all-i-want-for-christmas.mp3` |
| Post Malone — Circles | `public/api/music.mp3` |
| Ariana Grande — Santa Tell Me | `public/api/music-files/santa-tell-me.mp3` |
| 아이유 — 미리 메리 크리스마스 | `public/api/music-files/iu-merry-christmas.mp3` |
| Wham! — Last Christmas | `public/api/music-files/last-christmas.mp3` |

`npm run dev`는 사이트와 음원 Worker를 함께 실행하며 같은 로컬 MP3를 사용합니다. 사이트의 `/api/music/곡ID`는 로그인을 확인한 뒤 비공개 음원 서비스에 접근합니다. 기존 `/api/music` 주소는 Circles를 제공합니다. 바꾼 곡은 브라우저 캐시 때문에 최대 1시간 뒤에 반영될 수 있습니다.

일반 사이트 업데이트와 GitHub 자동 배포는 `npm run deploy`만 실행합니다. 사이트의 `.assetsignore`는 MP3를 제외하고 기존 음원 서비스를 그대로 연결하므로, 빌드 환경에 MP3가 없어도 배경음악이 유지됩니다. `npm run deploy:music`는 모든 곡의 파일과 크기를 먼저 검사해 파일이 빠진 상태에서 음원 서비스를 덮어쓰는 것을 막습니다. 음원 서비스에는 사이트용 Workers Builds 자동 배포를 연결하지 않습니다.

## 웹 게임 상태

- Workers가 정적 화면, 로그인과 게임 API를 제공합니다.
- SQLite 기반 Durable Object가 방마다 게임 상태를 보존하고 WebSocket으로 변경을 알립니다. 이후 참가자가 조회하는 상태에는 자신이 볼 수 있는 정보만 포함됩니다. 브라우저를 닫았다 다시 접속해도 대전을 이어갈 수 있습니다.
- 대전 게임 랭킹은 게임별 점수 순입니다. 점수는 Elo 방식으로 계산합니다. 모두 1000점에서 시작하고(K=32), 점수가 높은 상대를 이기면 많이, 낮은 상대를 이기면 적게 오릅니다. 3~4인 게임은 승자가 패자 각각을 이긴 것으로 계산합니다. 단독 승리로 2연승 이상 하면 연승 보너스로 (연승 수 − 1) × 2점, 최대 10점을 더 받습니다. 연패에는 불이익이 없습니다. 자리를 이어받은 판과 둘 다 포기한 판은 반영하지 않습니다.
- 섯다는 점수 대신 돈으로 랭킹을 매깁니다. 모든 계정은 1,000만원에서 시작하고, D1의 `wallets`에 잔액과 파산 횟수를 저장합니다. 판이 끝나면 각자 딴 돈과 잃은 돈을 반영하고(판 도중 나간 사람 포함), 다음 판은 방이 D1에서 다시 읽은 잔액으로 시작합니다. 잔액이 10만원 이하이면 다음 판을 시작할 때 파산 처리하고 300만원으로 다시 채웁니다.
- D1이 계정과 세션, 방 목록, 랭킹을 저장합니다. 완료한 싱글 게임은 서버가 입력 기록을 재생해 점수를 계산합니다. 웹의 싱글 랭킹 한 판은 최대 30분입니다.
